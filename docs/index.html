Open WebUI browser automation

Give Open WebUI a browser—without giving up control.

A small, self-hosted workspace that connects Open WebUI to Playwright MCP and Chromium through an authenticated OpenAPI bridge. Choose an isolated headless browser or a visible session you can supervise through noVNC.

Only the authenticated bridge joins the Open WebUI network. Browser-control services stay on a private browser network.

What this repository provides

◎

Headless automation ↗

Isolated Chromium for normal page navigation and automation, with no persistent profile or viewer.

◉

Visible automation ↗

A persistent headed Chromium session that can be watched and manually controlled through noVNC.

⌘

OpenAPI connection ↗

Register the bridge as a server-side Open WebUI tool connection using a separate bearer key.

▣

Explicit boundaries ↗

Private network bindings, strict authentication, and guidance for human approval of consequential actions.

⚠

This is a browser-control service, not a complete agent safety system. Start with public, read-only tasks and add approvals before purchases, messages, uploads, deletions, or account changes.

Quickstart

These add-ons extend an existing Open WebUI installation. They do not install Open WebUI or a model.

Prerequisites

  • Linux host with Docker Engine and Compose v2.
  • Git, Bash, and OpenSSL.
  • Open WebUI attached to a user-defined Docker network.
  • Open WebUI administrator access and a model/provider that supports tool calling.
  • SSH access to the Docker host when using the visible viewer.
check the host
docker info
docker compose version
git --version
openssl version

Clone the repository

bash
git clone https://github.com/AngelN-Halo/open-webui-browser-workspace.git open-webui-browser-workspace
cd open-webui-browser-workspace

Find the Open WebUI network

The selected network must already exist and must be a user-defined bridge network used by the Open WebUI container. Do not use Docker's built-in bridge, host, or none networks.

bash
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}'
docker inspect OPEN_WEBUI_CONTAINER --format '{{range $name, $_ := .NetworkSettings.Networks}}{{println $name}}{{end}}'
docker network ls

Set the network before running the add-on setup script:

bash
export OPEN_WEBUI_NETWORK=YOUR_NETWORK_NAME

Setup writes this value to the add-on's .env. If that file already exists, setup leaves it unchanged. An exported variable overrides .env during Compose commands, so keep them consistent or run unset OPEN_WEBUI_NETWORK.

Headless browser

Use headless mode for ordinary browser automation when you do not need to watch or preserve a login session. Chromium runs isolated and has no persistent profile volume.

bash
cd addons/headless-browser
./setup.sh
docker compose pull
docker compose up -d
docker compose ps -a
docker compose logs --tail=100

Setup generates a private API key and validates Compose; it does not start containers or verify that the external network exists. Expect playwright and browser-tools to remain running.

ⓘ

The headless bridge is reachable by Open WebUI at http://browser-tools:8000 over the shared Docker network. It publishes no host port.

Visible browser with noVNC

Use visible mode when you need to observe automation, complete a login or MFA step yourself, or retain a browser profile. The profile volume contains cookies and sessions.

bash
cd addons/visible-browser
./setup.sh
docker compose build visible-browser-session
docker compose pull visible-playwright visible-browser-tools
docker compose up -d
docker compose ps -a

The first build downloads Chromium and desktop dependencies and may take several minutes. Expect visible-browser-session, visible-playwright, and visible-browser-tools to remain running. There are no readiness health checks; allow Chromium time to start.

⚠

The visible browser is single-user/single-session, not isolated per chat or user. Anyone allowed to invoke this server may be able to use its logged-in accounts.

Configuration

VariablePurposeDefault / behavior
BROWSER_TOOLS_API_KEYBearer key protecting the OpenAPI bridge.Setup generates a 32-byte random hex key.
OPEN_WEBUI_NETWORKExisting Docker network shared with Open WebUI.open-webui_default
VISIBLE_BROWSER_PROFILE_VOLUMEPersistent profile volume for visible Chromium.open-webui_visible-browser-profile; visible only.

Both add-ons ship an environment template. The visible template adds the profile-volume setting. Do not use the example replacement key as a production credential.

Connect to Open WebUI

In Open WebUI administrator settings, find External Tools or Tool Servers (the label varies by version). Add a server-side connection and select OpenAPI.

FieldHeadlessVisible
NameBrowser — HeadlessBrowser — Visible
Base URLhttp://browser-tools:8000http://visible-browser-tools:8000
Schema path/openapi.json
AuthenticationBearer
KeyThe selected add-on's BROWSER_TOOLS_API_KEY
  1. If the UI requests a complete schema URL, append /openapi.json.
  2. Paste only the key value into the Bearer field.
  3. Enable the chosen server's tools in a chat with a tool-capable model.
ⓘ

These service names are Docker-internal URLs. They are not workstation URLs. A personal/direct tool connection running from your web browser cannot reach them.

Open the visible viewer

Visible mode publishes noVNC on host loopback only. From your workstation, create an SSH tunnel to the Docker host:

bash
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:6080:127.0.0.1:6080 USER@DOCKER_HOST

Then open http://127.0.0.1:6080/vnc.html and click Connect. If local port 6080 is occupied, use another workstation port:

bash
ssh -N -L 127.0.0.1:6081:127.0.0.1:6080 USER@DOCKER_HOST

Open http://127.0.0.1:6081/vnc.html. The viewer has no VNC password; SSH and loopback binding are the intended protections.

Human handoff and persistent sessions

  1. Enable only the visible browser server in the chat.
  2. Ask the model to navigate to the login page and wait.
  3. Wait for active tool calls to finish, then open noVNC.
  4. Type credentials and complete MFA yourself.
  5. Tell the model exactly which task and actions it may resume.
  6. Log out when the account context should no longer be available.
⚠

The human and model share one browser. Avoid simultaneous input. Closing the viewer, ending a chat, or restarting the container does not clear the visible profile.

Security

Read the repository's complete SECURITY.md before using sensitive workflows.

  • Do not publish ports 8000, 8931, 9222, 5900, or 6080 publicly.
  • Use a dedicated, least-privileged Open WebUI account and a separate browser profile.
  • Keep API keys in private .env files; never put secrets in prompts.
  • Require human approval for purchases, messages, uploads, deletions, and account changes.
  • Treat website content as untrusted input; page instructions can be prompt injection.
  • The default Playwright containers use --no-sandbox for compatibility. For untrusted tasks or stronger isolation, use a disposable VM and egress policy.

Operations

Inspect and restart

bash
docker compose config --quiet
docker compose ps -a
docker compose logs --tail=100

docker compose stop
docker compose start
docker compose down

docker compose down removes containers and the Compose-managed network but retains the visible profile volume by default. Adding --volumes deletes declared volumes, including saved sessions.

Update

Stop active automation and review upstream changes first. The images use moving tags such as latest, main, and 12-slim; pin tested versions or digests if repeatability matters.

headless
git pull --ff-only
docker compose pull
docker compose up -d
visible
git pull --ff-only
docker compose build --pull --no-cache visible-browser-session
docker compose pull visible-playwright visible-browser-tools
docker compose up -d --force-recreate

Troubleshooting

SymptomCheck
External network not foundConfirm Open WebUI created a user-defined network and correct OPEN_WEBUI_NETWORK before setup.
Open WebUI cannot connectCheck that both containers share the selected network and use the Docker service URL, not localhost.
401 or 403Use the key from the correct add-on's .env; recreate the bridge and update the saved connection after rotation.
Schema loads, tools failInspect Playwright and bridge logs; visible mode may need more startup time.
Model does not use toolsEnable the server in the chat and confirm the model/provider supports tool calling.
noVNC will not loadKeep the SSH tunnel open, verify the local port, and check the session container.
Visible browser never changesEnable only the visible server. Headless controls a different browser.
Profile needs resetUse a new profile volume; do not delete the old volume until its contents are understood.

Review logs before sharing them. Browser URLs, page content, and sensitive details may appear.
